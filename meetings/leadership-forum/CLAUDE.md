## Document Structure

The doc is a reverse-chronological stack of session entries (newest first). Each entry contains:

```
[Date]

Key Metrics (standing section):
- [Metric 1]: [value]
- [Metric 2]: [value]
- [Metric 3]: [value]

Topic #1: [Title]
[Content — typically a strategic update, experiment readout, or decision request]

Topic #2: [Title]
[Content]
```

### Recurring Topic Types

| Category | Examples |
|----------|---------|
| GTM Update | Adoption metrics, migration status, launch updates |
| Performance | Experiment readouts, model performance, efficiency metrics |
| Strategy | Roadmap decisions, resource allocation, cross-team partnerships |
| Risks | Churn analysis, competitive threats, technical debt |

---

## How This Differs from Weekly Meetings

| | Weekly Meeting | Leadership Forum |
|---|---|---|
| **Audience** | Working team | Leadership + team leads |
| **Cadence** | Weekly | Bi-weekly |
| **Focus** | Tactical project updates, blockers | Strategic topics with data and analysis |
| **Depth** | Status updates per project | Deep dives on 2-3 topics |

---

## Workflow

1. Read the most recent entry in the Google Doc
2. Pull meeting notes from the past 2 weeks for relevant meetings
3. Check the roadmap spreadsheet for status changes and upcoming milestones
4. Draft the new entry with updated metrics and 2-3 discussion topics
5. Save as `meetings/leadership-forum/MMDDYY/update.md`
6. Insert into Google Doc after PM approval

---

## Conventions

- Key metrics always lead the entry
- Topics are numbered (Topic #1, Topic #2, etc.)
- Each topic has a clear title and supporting data
- This is a leadership audience — strategic, not tactical
- Experiment readouts include: problem, solution, results, next steps
